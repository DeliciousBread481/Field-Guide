You can add new categories, reorganize existing ones, or add modded entities to the Field Guide using standard Minecraft **Datapacks**.

### Defining Categories

Category files are JSON files located at:
`data/<namespace>/fieldguide/categories/<filename>.json`

The filename becomes the ID of the category (e.g., `wetlands.json` becomes `<namespace>:wetlands`).

#### JSON Structure

| Field        | Type    | Description                                                                          |
|--------------|---------|--------------------------------------------------------------------------------------|
| `sort_index` | Integer | Determines the tab order (lower numbers are first).                                  |
| `replace`    | Boolean | (Optional) If true, clears existing entries in this category before adding new ones. |
| `contents`   | Array   | A list of entry objects.                                                             |

#### Removing Default Categories

To remove a category provided by the mod (or another datapack), create a file with the **same ID** and use `"replace": true` with an empty contents list.
The Field Guide automatically hides empty categories.

**Example:** Removing the default `monsters` category:

`data/fieldguide/fieldguide/categories/monsters.json`

```json
{
  "replace": true,
  "contents": []
}

```

#### Content Types

1. **Manual Entry:** Adds a specific Entity or Block.

```json
{
  "type": "entry",
  "id": "minecraft:pig"
}

```

2. **Auto-Populate:** Automatically adds entries based on a preset strategy.

```json
{
  "type": "auto_populate",
  "strategy": "monsters"
}

```

*Available Strategies*:

* `animals`: All animals.
* `monsters`: All monsters.
* `plants`: All vanilla-like plants. (Automatically groups tree saplings, logs, leaves, wood, and stems into a single entry)
* `mod:<mod_id>`: All entities from a specific mod.
* `mod_plants:<mod_id>`: All plant-like blocks from a specific mod. (Automatically groups tree saplings, logs, leaves, wood, and stems into a single entry)
* `tag:<tag_id>`: All entities with a specific tag (e.g. tag:minecraft:raiders).

3. **Composite Entry:** A special entry type that allows you to combine multiple entities, render a structure from an NBT file, or display a stack of blocks.

```json
{
  "type": "composite",
  "id": "mypack:custom_boss_encounter",
  "display_id": "minecraft:zombie",
  "components": [
    "minecraft:zombie",
    "minecraft:skeleton"
  ],
  "structure_nbt": "mypack:structures/spawner_room",
  "stacked_blocks": [
    "minecraft:cobblestone",
    "minecraft:mossy_cobblestone"
  ]
}

```

* `id`: The unique identifier for this custom entry.
* `display_id` *(Optional)*: The primary entity or block ID to represent this entry in the UI.
* `components` *(Optional)*: An array of entity/block IDs that make up this composite entry. Scanning any of these will relate back to this entry.
* `structure_nbt` *(Optional)*: The resource location of an NBT structure file to render in the book.
* `stacked_blocks` *(Optional)*: An array of block IDs to render stacked on top of each other.

#### Example: Custom Category

`data/mypack/fieldguide/categories/swamp_life.json`

```json
{
  "sort_index": 5,
  "contents": [
    {
      "type": "entry",
      "id": "minecraft:frog"
    },
    {
      "type": "entry",
      "id": "minecraft:witch"
    },
    {
      "type": "entry",
      "id": "minecraft:lily_pad"
    }
  ]
}

```

### Special Entity Tags

Field Guide uses specific entity tags that you can add to your datapacks to change scanning behavior:

* `fieldguide:bosses`: Entities with this tag are excluded from the `monsters` and `animals` auto-populate strategies, and are moved to a special `bosses` category.
* `fieldguide:kill_to_unlock`: Entities with this tag can't be scanned with a spyglass: you have to kill them to unlock their entry (defaults to all bosses).

### Biome & Loot Modifiers

Field Guide uses datapacks to modify which biomes and loot drops appear on an entry's page. This is useful for correcting missing information or hiding unwanted drops.

#### File Locations
* **Biome Modifiers:** `data/<namespace>/fieldguide/biome_modifiers/<filename>.json`
* **Loot Modifiers:** `data/<namespace>/fieldguide/loot_modifiers/<filename>.json`

#### JSON Structure
Both biome and loot modifiers use the exact same layout. You can define `additions` and `removals` within the same file.

You can use either `entry` (single string) or `entries` (array of strings) to define the target pages, and `value` or `values` to define the biomes/items being added or removed.

**Example Biome Modifier:** (`data/mypack/fieldguide/biome_modifiers/warden_fix.json`)
```json
{
  "replace": false,
  "additions": [
    {
      "entry": "minecraft:warden",
      "values": [
        "minecraft:deep_dark"
      ]
    }
  ],
  "removals": [
    {
      "entries": [
        "minecraft:pig",
        "minecraft:cow"
      ],
      "value": "minecraft:badlands"
    }
  ]
}

```

**Example Loot Modifier:** (`data/mypack/fieldguide/loot_modifiers/cow_milk.json`)
```json
{
  "additions": [
    {
      "entry": "minecraft:cow",
      "value": "minecraft:milk_bucket"
    }
  ],
  "removals": [
    {
      "entry": "minecraft:skeleton",
      "values": [
        "minecraft:arrow",
        "minecraft:bone"
      ]
    }
  ]
}

```

*Note: Setting `"replace": true` at the root of the JSON will clear all previously loaded modifiers of that type (from the mod or other datapacks) before applying yours.*

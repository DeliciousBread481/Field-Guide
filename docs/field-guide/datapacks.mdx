You can add new categories, reorganize existing ones, or add modded entities to the Field Guide using standard Minecraft **Datapacks**.

### Defining Categories

Category files are JSON files located at:
`data/<namespace>/fieldguide/categories/<filename>.json`

The filename becomes the ID of the category (e.g., `wetlands.json` becomes `<namespace>:wetlands`).

#### JSON Structure

| Field | Type | Description |
| --- | --- | --- |
| `sort_index` | Integer | Determines the tab order (lower numbers are first). |
| `icon` | String | (Optional) The Resource Location for the category's tab icon. |
| `replace` | Boolean | (Optional) If true, clears existing entries in this category before adding new ones. |
| `contents` | Array | A list of entry objects. |

#### Removing Default Categories

To remove a category provided by the mod (or another datapack), create a file with the **same ID** and use `"replace": true` with an empty contents list.
The Field Guide automatically hides empty categories.

**Example:** Removing the default `monsters` category:

`data/fieldguide/fieldguide/categories/monsters.json`

```json
{
  "replace": true,
  "contents": []
}

```

#### Content Types

1. **Manual Entry:** Adds a specific Entity, Block, or Item.

```json
{
  "type": "entry",
  "id": "minecraft:pig"
}

```

2. **Auto-Populate:** Automatically adds entries based on a preset strategy.

```json
{
  "type": "auto_populate",
  "strategy": "monsters"
}

```

*Available Strategies*:

* `animals`: All animals.
* `monsters`: All monsters.
* `plants`: All vanilla-like plants.
* `auto_trees`: Automatically generates tree composites for all saplings in a mod. It looks for `_leaves` and `_log` blocks that share the same base name as the sapling (e.g., `oak_sapling` -> `oak_leaves` and `oak_log`). It generates a simplified 8-block tall tree structure for display.
* `mod:<mod_id>`: All entities from a specific mod.
* `mod_plants:<mod_id>`: All plant-like blocks from a specific mod.
* `mod_trees:<mod_id>`: All dynamically generated tree structures from a specific mod.
* `mod_items:<mod_id>`: All items from a specific mod.
* `tag:<tag_id>`: All entities, blocks and items with a specific tag (e.g., `tag:minecraft:raiders` or `tag:minecraft:logs`).

#### Content grouping

By default entries in the list appear in the order they were defined in `content: []`. However, if you want similar entries to be grouped together, a list of ['search queries'](/project/field-guide/docs/field-guide/searching) can be provided in `group_by`.

Entries matched by the first query will show up first on the list, followed by entries matching the second, then third and so on. Entries that don't match any query will appear last on the list.

```json
{
  "replace": false,
  "group_by": [
        "tree",
        "#minecraft:flowers",
        "!forest"
        "!ocean"
  ],
  "contents": [...]
}

```

### For Mod Developers & Pack Makers

If you are a mod developer, you can ensure your mod plays nicely with Field Guide by providing your own built-in datapack data. Here are some tips and advanced entry types to help you integrate seamlessly.

#### Plant blocks

The default "Plants" category includes everything with the tag `fieldguide:plants`. To make sure your modded plant blocks show up, either apply this tag or one of the following:

* `minecraft:flowers`
* `minecraft:saplings`
* `minecraft:crops`
* `minecraft:corals`
* `minecraft:tall_flowers`
* `minecraft:leaves`

#### Special Entity Tags

Field Guide uses specific entity tags to handle default scanning and categorization behaviors. Apply these tags to your mod's entities where appropriate:

* `fieldguide:bosses`: Entities with this tag are excluded from the `monsters` and `animals` auto-populate strategies, and are moved to a special `bosses` category. **Note: Bosses are also set to "Kill to Unlock" by default.**
* `fieldguide:kill_to_unlock`: Entities with this tag can't be scanned with a spyglass or the naked eye: the player must kill them to unlock their entry. (Defaults to all bosses).

#### Discovery Redirects

Sometimes you may want scanning one entity to unlock the entry for a different one. This is useful for entities that have multiple variations or distinct parts (like multi-part bosses) where scanning any part should unlock the main entry.

The redirected block/entity will automatically be removed from categories and will no longer appear as its own entry.

You can define these redirects by creating a JSON file at:
`data/<namespace>/fieldguide/redirects/<filename>.json`

```json
{
  "entries": [
    {
      "source": "farmersdelight:budding_tomatoes",
      "target": "farmersdelight:tomatoes"
    },
    {
      "source": "enemyexpansion:vampire_biter",
      "target": "enemyexpansion:vampire"
    }
  ]
}

```

#### Composite Entries

A **Composite Entry** is a powerful feature that allows you to group multiple entities or blocks into a single book page, or render custom scenes using NBT structures.

The composite will replace any of the component blocks if they are included in a category. The individual components will automatically be removed from all categories.

This is highly recommended for multi-block entries, structures, or grouped concepts (like grouping all tree blocks for a specific tree).

You can define composites by creating a JSON file at:
`data/<namespace>/fieldguide/composites/<filename>.json`

```json
{
    "values": [
        {
            "id": "farmersdelight:rice",
            "render": [
                "farmersdelight:rice|age=3,supporting=true",
                "farmersdelight:rice_panicles|age=3"
            ],
            "components": [
                "farmersdelight:rice",
                "farmersdelight:rice_panicles"
            ],
        },
        {
            "id": "minecraft:mangrove_propagule",
            "structure_nbt": "fieldguide:mangrove",
            "components": [
                "minecraft:mangrove_log",
                "minecraft:mangrove_leaves",
                "minecraft:mangrove_roots",
                "minecraft:muddy_mangrove_roots"
            ]
        },
    ]
}
```

* `id`: The unique identifier for this custom entry.
* `display_id` *(Optional)*: The primary entity or block ID to represent this entry in the UI.
* `components` *(Optional)*: An array of entity/block IDs that make up this composite entry. These will no longer appear individually as entries.
* `structure_nbt`: Provide the resource location of an NBT structure file to render. *(Tip: You can use the `/fieldguide export feature <feature_id>` command in-game to easily generate an NBT file of a worldgen feature!)*
* `render`: An alternative to `structure_nbt` for simpler structures. Provide an array of block IDs to render. By default, blocks will stack on top of each other vertically. You can also specify exact 3D coordinates for each block using the format `"X,Y,Z|block_id"`.

### Variants

Modpack/mod creators can manually define variants for entities using NBT. This is useful for mods that use custom variant systems that Field Guide can't automatically detect, or for adding custom variants via other datapacks.

Variants can be defined by creating a JSON file at:
`data/<namespace>/fieldguide/variants/<filename>.json`

```json
{
  "entries": [
    {
      "id": "minecraft:wolf",
      "replace": false,
      "variants": [
        {
          "id": "pale",
          "nbt": "{variant: \"minecraft:pale\"}"
        },
        {
          "id": "woods",
          "nbt": "{variant: \"minecraft:woods\"}"
        }
      ]
    }
  ]
}
```

* `id`: The unique identifier for the entity type.
* `replace` *(Optional)*: If set to `true`, all existing variants for this entity (including auto-detected ones) will be removed before adding these new ones.
* `variants`: A list of variant definitions.
    * `id`: A unique ID for the variant. This ID is used for translation keys in the format `entity.<namespace>.<entity_id>.variant.<variant_id>` (e.g., `entity.minecraft.wolf.variant.pale`).
    * `nbt`: The NBT string to apply to the entity to set this variant. This is also used to detect if an entity has this variant by comparing the provided NBT against the entity's current NBT.

### Biome & Loot Modifiers

Field Guide uses datapacks to modify which biomes and loot drops appear on an entry's page.
This is useful for correcting missing information or hiding unwanted drops.

#### File Locations

* **Biome Modifiers:** `data/<namespace>/fieldguide/biome_modifiers/<filename>.json`
* **Loot Modifiers:** `data/<namespace>/fieldguide/loot_modifiers/<filename>.json`

#### JSON Structure

Both biome and loot modifiers use the exact same layout.
You can define `additions` and `removals` within the same file.
You can use either `entry` (single string) or `entries` (array of strings) to define the target pages, and `value` or `values` to define the biomes/items being added or removed.

**Example Biome Modifier:** (`data/mypack/fieldguide/biome_modifiers/warden_fix.json`)

```json
{
  "replace": false,
  "additions": [
    {
      "entry": "minecraft:warden",
      "values": [
        "minecraft:deep_dark"
      ]
    }
  ],
  "removals": [
    {
      "entries": [
        "minecraft:pig",
        "minecraft:cow"
      ],
      "value": "minecraft:badlands"
    }
  ]
}

```

**Example Loot Modifier:** (`data/mypack/fieldguide/loot_modifiers/cow_milk.json`)

```json
{
  "additions": [
    {
      "entry": "minecraft:cow",
      "value": "minecraft:milk_bucket"
    }
  ],
  "removals": [
    {
      "entry": "minecraft:skeleton",
      "values": [
        "minecraft:arrow",
        "minecraft:bone"
      ]
    }
  ]
}

```

*Note: Setting `"replace": true` at the root of the JSON will clear all previously loaded modifiers of that type (from the mod or other datapacks) before applying yours.*

### Blacklisting Entries

If you want to hide specific entities, blocks, or items from the Field Guide entirely, or just hide them from a specific category, you can do so using tags.

**Global Blacklists:**
To completely remove an entity, block, or item from all categories and scanning mechanics, add its ID to the `fieldguide:blacklisted` tag.

* **Entities:** `data/fieldguide/tags/entity_type/blacklisted.json`
* **Blocks:** `data/fieldguide/tags/block/blacklisted.json`
* **Items:** `data/fieldguide/tags/item/blacklisted.json`

*Example (`data/fieldguide/tags/entity_type/blacklisted.json`):*
```json
{
  "replace": false,
  "values": [
    "minecraft:armor_stand",
    "minecraft:giant",
    "minecraft:illusioner"
  ]
}

```

**Per-Category Blacklists:**
You can also blacklist entries from appearing in *specific* categories without hiding them globally. To do this, create a tag formatted as `fieldguide:blacklisted/<category_namespace>/<category_path>`.

For example, to prevent Zombie Piglins from appearing in the `fieldguide:monsters` category (but allow them to appear elsewhere), you would create this file:

*File:* `data/fieldguide/tags/entity_type/blacklisted/fieldguide/monsters.json`

```json
{
  "replace": false,
  "values": [
    "minecraft:zombified_piglin"
  ]
}

```

This works for `entity_type`, `block`, and `item` tags.

You can add new categories, reorganize existing ones, or add modded entities to the Field Guide using standard Minecraft **Datapacks**.

### Defining Categories

Category files are JSON files located at:
`data/<namespace>/fieldguide/categories/<filename>.json`

The filename becomes the ID of the category (e.g., `wetlands.json` becomes `<namespace>:wetlands`).

#### JSON Structure

| Field | Type | Description |
| --- | --- | --- |
| `sort_index` | Integer | Determines the tab order (lower numbers are first). |
| `icon` | String | (Optional) The Resource Location for the category's tab icon. |
| `replace` | Boolean | (Optional) If true, clears existing entries in this category before adding new ones. |
| `contents` | Array | A list of entry objects. |

#### Removing Default Categories

To remove a category provided by the mod (or another datapack), create a file with the **same ID** and use `"replace": true` with an empty contents list.
The Field Guide automatically hides empty categories.

**Example:** Removing the default `monsters` category:

`data/fieldguide/fieldguide/categories/monsters.json`

```json
{
  "replace": true,
  "contents": []
}

```

#### Content Types

1. **Manual Entry:** Adds a specific Entity or Block.

```json
{
  "type": "entry",
  "id": "minecraft:pig"
}

```

2. **Auto-Populate:** Automatically adds entries based on a preset strategy.

```json
{
  "type": "auto_populate",
  "strategy": "monsters"
}

```

*Available Strategies*:

* `animals`: All animals.
* `monsters`: All monsters.
* `plants`: All vanilla-like plants.
* `auto_trees`: All dynamically generated tree structures (vanilla and modded).
* `mod:<mod_id>`: All entities from a specific mod.
* `mod_plants:<mod_id>`: All plant-like blocks from a specific mod.
* `mod_trees:<mod_id>`: All dynamically generated tree structures from a specific mod.
* `tag:<tag_id>`: All entities and blocks with a specific tag (e.g., `tag:minecraft:raiders` or `tag:minecraft:logs`).

#### Content grouping

By default entries in the list appear in the order they were defined in `content: []`. However, if you want similar entries to be grouped together, a list of ['search queries'](/project/field-guide/docs/field-guide/searching) can be provided in `group_by`.

Entries matched by the first query will show up first on the list, followed by entries matching the second, then third and so on. Entries that don't match any query will appear last on the list.

```json
{
  "replace": false,
  "group_by": [
        "tree",
        "#minecraft:flowers",
        "!forest"
        "!ocean"
  ],
  "contents": [...]
}

```

### For Mod Developers & Pack Makers

If you are a mod developer, you can ensure your mod plays nicely with Field Guide by providing your own built-in datapack data. Here are some tips and advanced entry types to help you integrate seamlessly.

#### Plant blocks

The default "Plants" category includes everything with the tag `fieldguide:plants`. To make sure your modded plant blocks show up, either apply this tag or one of the following:

* `minecraft:flowers`
* `minecraft:saplings`
* `minecraft:crops`
* `minecraft:corals`
* `minecraft:tall_flowers`
* `minecraft:leaves`

#### Special Entity Tags

Field Guide uses specific entity tags to handle default scanning and categorization behaviors. Apply these tags to your mod's entities where appropriate:

* `fieldguide:bosses`: Entities with this tag are excluded from the `monsters` and `animals` auto-populate strategies, and are moved to a special `bosses` category.
* `fieldguide:kill_to_unlock`: Entities with this tag can't be scanned with a spyglass: the player must kill them to unlock their entry (defaults to all bosses).

#### Discovery Redirects

Sometimes you may want scanning one entity to unlock the entry for a different one. This is useful for entities that have multiple variations or distinct parts (like multi-part bosses) where scanning any part should unlock the main entry.

You can define these redirects by creating a JSON file at:
`data/<namespace>/fieldguide/redirects/<filename>.json`

```json
{
  "entries": [
    {
      "source": "minecraft:bamboo_sapling",
      "target": "minecraft:bamboo"
    },
    {
      "source": "enemyexpansion:vampire_biter",
      "target": "enemyexpansion:vampire"
    }
  ]
}

```

#### Composite Entries

A **Composite Entry** is a powerful feature that allows you to group multiple entities or blocks into a single book page, or render custom scenes using NBT structures.

This is highly recommended for multi-block entries, structures, or grouped concepts (like grouping all tree blocks for a specific tree).

```json
{
  "type": "composite",
  "id": "mypack:custom_boss_encounter",
  "display_id": "minecraft:zombie",
  "components": [
    "minecraft:zombie",
    "minecraft:skeleton"
  ],
  "structure_nbt": "mypack:structures/spawner_room",
  "stacked_blocks": [
    "0,0,0|minecraft:cobblestone",
    "0,1,0|minecraft:mossy_cobblestone"
  ]
}

```

* `id`: The unique identifier for this custom entry.
* `display_id` *(Optional)*: The primary entity or block ID to represent this entry in the UI.
* `components` *(Optional)*: An array of entity/block IDs that make up this composite entry.
* `structure_nbt` *(Optional)*: The resource location of an NBT structure file to render in the book. *(Tip: You can use the `/fieldguide export feature <feature_id>` command in-game to easily generate an NBT file of a worldgen feature!)*
* `stacked_blocks` *(Optional)*: An array of block IDs to render. By default, items will stack on top of each other vertically. You can also specify exact 3D coordinates using the format `"X,Y,Z|block_id"`.

### Biome & Loot Modifiers

Field Guide uses datapacks to modify which biomes and loot drops appear on an entry's page.
This is useful for correcting missing information or hiding unwanted drops.

#### File Locations

* **Biome Modifiers:** `data/<namespace>/fieldguide/biome_modifiers/<filename>.json`
* **Loot Modifiers:** `data/<namespace>/fieldguide/loot_modifiers/<filename>.json`

#### JSON Structure

Both biome and loot modifiers use the exact same layout.
You can define `additions` and `removals` within the same file.
You can use either `entry` (single string) or `entries` (array of strings) to define the target pages, and `value` or `values` to define the biomes/items being added or removed.

**Example Biome Modifier:** (`data/mypack/fieldguide/biome_modifiers/warden_fix.json`)

```json
{
  "replace": false,
  "additions": [
    {
      "entry": "minecraft:warden",
      "values": [
        "minecraft:deep_dark"
      ]
    }
  ],
  "removals": [
    {
      "entries": [
        "minecraft:pig",
        "minecraft:cow"
      ],
      "value": "minecraft:badlands"
    }
  ]
}

```

**Example Loot Modifier:** (`data/mypack/fieldguide/loot_modifiers/cow_milk.json`)

```json
{
  "additions": [
    {
      "entry": "minecraft:cow",
      "value": "minecraft:milk_bucket"
    }
  ],
  "removals": [
    {
      "entry": "minecraft:skeleton",
      "values": [
        "minecraft:arrow",
        "minecraft:bone"
      ]
    }
  ]
}

```

*Note: Setting `"replace": true` at the root of the JSON will clear all previously loaded modifiers of that type (from the mod or other datapacks) before applying yours.*
